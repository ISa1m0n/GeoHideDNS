# hosts-ai для GeoHideDNS

**Компактный hosts-список AI- и dev-сервисов, собранный из публичного GeoHide.**

[![Update filtered GeoHide hosts](https://github.com/ISa1m0n/GeoHideDNS/actions/workflows/update-hosts.yml/badge.svg?branch=main)](https://github.com/ISa1m0n/GeoHideDNS/actions/workflows/update-hosts.yml)

</div>

## Что это

[GeoHide](https://github.com/Internet-Helper/GeoHideDNS) - публичный Smart DNS: он отдаёт
hosts-файл с адресами сервисов, которые не открываются напрямую. Файл большой - сотни
доменов, часть которых не нужна, часть уже мертва.

Этот форк собирает из него **свой список** - `hosts-ai.txt`: только нужные разделы,
только рабочие адреса, плюс ручные закрепления. Пересобирается раз в сутки, после каждого
изменения конфигов и сразу после того, как проверка с ПК переписала `health.txt`.

## Что получается

Примерно 297 записей в 31 разделе, три адреса:

| Адрес | Что это |
|---|---|
| `MAIN` | основной EU-узел, на него идут почти все домены |
| `ALT` | второй EU-узел, только для apex `last.fm` и `deezer.com` (разнос www и apex) |
| `GEMINI` | адрес для Gemini и AI Studio, вне hosts GeoHide |

Конкретные IP живут в `health.txt` (их пишет проверка с ПК) или в `defaults.txt`.
Фактическое число записей всегда видно в шапке последнего коммита `hosts-ai.txt`.
Домены, которых нет в списке, идут через обычный DNS.

## Как работает сборка

`filter.sh` запускается в GitHub Actions и проходит пять шагов:

1. Скачивает свежие `hosts/eu/hosts` и `hosts/us/hosts` из апстрима.
2. Оставляет только разделы из `sections.txt`. Если раздел переименовали - сборка
   падает с ошибкой, а не выкидывает сервис молча.
3. Добавляет домены из `extra-domains.txt` - из любых разделов, независимо от выбора.
4. Подменяет домены из `us-domains.txt` строками US-hosts с указанным IP.
5. Выбирает живые адреса: `MAIN`, `ALT` и `GEMINI` берутся из `health.txt`, а если его
   нет - из `defaults.txt`. Все остальные "ядровые" EU-адреса считаются плохими, поэтому
   каждый домен идёт на `MAIN`. Затем применяются `bad-ips.txt`, закрепления из
   `pin-ips.txt` (`@MAIN`, `@ALT`) и последним слоем `custom-hosts.txt` (`@GEMINI`).
   Если `MAIN` не из EU-hosts, сборка падает, и старый `hosts-ai.txt` остаётся.

Перед публикацией работает защита от массовой потери: если записей собралось меньше 200
или их стало меньше 80% от прошлого файла, сборка падает и `hosts-ai.txt` не меняется.

Результат (`hosts-ai.txt`) коммитит бот. Push идёт с повторами и `pull --rebase`, чтобы
не падать от гонки с коммитом `health.txt`.

## Структура

| Файл | Роль |
|---|---|
| `hosts-ai.txt` | **готовый список** - его и забирают |
| `sections.txt` | какие разделы апстрима оставить |
| `extra-domains.txt` | домены вне выбранных разделов |
| `us-domains.txt` | домены, которые берутся из US-hosts |
| `pin-ips.txt` | закрепить домен и его поддомены на одном IP |
| `custom-hosts.txt` | ручные записи поверх всей сборки |
| `bad-ips.txt` | адреса, которые нельзя использовать |
| `skip-domains.txt` | домены, которые незачем включать (их блокирует список рекламы NextDNS) |
| `defaults.txt` | адреса по умолчанию (`MAIN`, `ALT`, `GEMINI`) |
| `health.txt` | **живые адреса**, пишет проверка с ПК, перекрывает `defaults.txt` |
| `tools/geohide-probe.ps1` | проверка адресов с ПК по расписанию, коммитит `health.txt` |
| `tools/run-probe-hidden.vbs` | запускает проверку без окна консоли (действие задачи Планировщика) |
| `filter.sh` | сам сборщик |
| `.github/workflows/` | расписание, пересборка по push, keepalive |

## Как применить

### Windows

Дописать записи из `hosts-ai.txt` в `C:\Windows\System32\drivers\etc\hosts`
(нужны права администратора). Удобнее держать их отдельным блоком с маркерами
`BEGIN` / `END`, чтобы обновлять целиком.

### Keenetic

В Web CLI (`<роутер>/a`) - по строке на домен:

```
ip host chatgpt.com 5.175.161.40
```

> **Лимит.** У Keenetic максимум **256** статических записей `ip host`,
> из них 2 служебных. 297 доменов туда не влезают: часть придётся выбрать
> или вынести на NextDNS.

### NextDNS

Через [DnsConf](https://github.com/ISa1m0n/DnsConf): он берёт `hosts-ai.txt`
как источник rewrites и обновляет их по расписанию. Rewrites в NextDNS
действуют на домен **и его поддомены**, поэтому отдельные `www.*` там не нужны.

## Что изменено относительно апстрима

- Выбрано 30 разделов вместо всех. Убраны `Canva`, `Chess`, `Oracle`, `Supercell`:
  GeoHide их не проксирует, а обычный DNS для них лучше.
- `custom-hosts.txt` закрепляет Gemini и AI Studio на адресе `@GEMINI`. В hosts GeoHide
  живых адресов без `google.com/sorry` не осталось.
- `us-domains.txt` отключён: US-адреса GeoHide перестали отвечать.
- Удалены служебные копии `lists/` и `hosts/*` - сборка их не использует,
  всё качается из апстрима.

## Автопроверка адресов

GitHub Actions не видит блокировок РКН (раннер в США), поэтому живость адресов проверяет
`tools/geohide-probe.ps1` на ПК, через Планировщик заданий раз в 30 минут. Он проверяет TLS
до `claude.ai`, `chatgpt.com` и `platform.claude.com` по каждому EU-адресу, выбирает самый
быстрый живой (`MAIN`) и второй (`ALT`), а для Gemini ищет адрес без `/sorry`.

Дальше цепочка такая:

1. Если адреса отличаются от `health.txt` в форке, скрипт коммитит новый `health.txt`
   через GitHub API. Сам файл в локальном клоне не правится, он приедет обычным `git pull`.
2. Коммит запускает `update-hosts.yml`, тот пересобирает `hosts-ai.txt`.
3. Скрипт дожидается, пока в пересобранном файле появятся новые адреса (до 4 минут),
   и только после этого отправляет `repository_dispatch` в DnsConf, тот накатывает
   rewrites в NextDNS. Если диспатч не прошёл, через час всё сделает крон.

При включённом VPN или запущенном zapret проверка пропускается: результат был бы ложным.
Журнал: `tools/geohide-probe.log`. При полном отказе (ни одного живого EU-адреса,
Gemini лёг) в трее появляется уведомление, не чаще раза в 6 часов на событие.

Статус Gemini пишется комментарием в `health.txt`: `clean` (чат работает),
`ai-only` (чат отдаёт `/sorry`, живой только AI Studio), `dead` (не отвечает ничего).

### Установка проверки на ПК

1. Склонировать репозиторий (например, `D:\OpenCode\GeoHideDNS`).
2. Положить рядом со скриптом токен: `tools\geohide-probe.token` - fine-grained,
   репозитории `ISa1m0n/GeoHideDNS` и `ISa1m0n/DnsConf`, право Contents: Read and write.
3. Задача в Планировщике: `wscript.exe "D:\OpenCode\GeoHideDNS\tools\run-probe-hidden.vbs"`,
   повтор каждые 30 минут, от имени текущего пользователя. Запускать `powershell.exe`
   напрямую нельзя: `-WindowStyle Hidden` прячет консоль уже после её создания, окно
   успевает мигнуть и снимает с фокуса игру в полноэкранном режиме. `wscript.exe` -
   GUI-приложение, консоль не создаётся вовсе; сам VBS стартует PowerShell скрытым
   и ждёт его завершения, чтобы Планировщик видел реальный статус задачи.
4. Проверить вручную: `powershell -File tools\geohide-probe.ps1 -DryRun` - покажет
   выбранные адреса и ничего не закоммитит.

Правки в клоне начинать с `git pull`: бот коммитит `hosts-ai.txt`, а проверка - `health.txt`.

## Как менять

- **Добавить сервис** - дописать раздел в `sections.txt` (название должно точно
  совпадать с заголовком `# ...` в `hosts/eu/hosts` апстрима).
- **Один домен** - добавить в `extra-domains.txt`.
- **Свой IP** - `custom-hosts.txt`, формат `домен IP`.
- **Убрать адрес** - `bad-ips.txt`.

После правки пересборка стартует сама (workflow слушает `push` по этим файлам).
