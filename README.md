## Что это

[GeoHide](https://github.com/Internet-Helper/GeoHideDNS) - публичный Smart DNS: он отдаёт
hosts-файл с адресами сервисов, которые не открываются напрямую. Файл большой - сотни
доменов, часть которых не нужна, часть уже мертва.

Этот форк собирает из него **свой список** - `hosts-ai.txt`: только нужные разделы,
только рабочие адреса, плюс ручные закрепления. Пересобирается раз в сутки, после каждого
изменения конфигов и сразу после того, как проверка с ПК переписала `health.txt`.

Готовый файл всегда доступен по прямой ссылке:

```
https://raw.githubusercontent.com/ISa1m0n/ai-hosts/main/hosts-ai.txt
```

## Форк специально не сливается с апстримом

Апстрим `Internet-Helper/GeoHideDNS` - репозиторий данных: в корне только `hosts/`, `lists/`
и README, и обновляются они несколько раз в день. Сливать его сюда не нужно и опасно:
кнопка **Sync fork** → **Discard N commits** заменит файлы форка этими данными, то есть
снесёт `filter.sh`, `sections.txt`, `custom-hosts.txt`, `tools/`, `hosts-ai.txt` и `health.txt`.

Данные приходят сами: при каждой сборке `filter.sh` скачивает `hosts/eu/hosts` и
`hosts/us/hosts` по прямой ссылке из апстрима. Если апстрим переименует раздел, сборка
упадёт с сообщением «раздел не найден» (проверка в шаге 0), а не соберёт список молча.

## Что получается

~295 записей в 30 разделах. Адресов три:

| Адрес | Роль |
|---|---|
| `MAIN` | основной узел, на него идут почти все домены |
| `ALT` | второй узел, только для apex `last.fm` и `deezer.com` (разнос www и apex) |
| `GEMINI` | адрес для Gemini и AI Studio, вне hosts GeoHide |

Конкретные IP живут в `health.txt` (их пишет проверка с ПК) или в `defaults.txt`.
Точное число записей печатает сама сборка в журнале Actions, шаг Build filtered hosts.
Домены, которых нет в списке, идут через обычный DNS.

## Как это работает

```
ПК: geohide-probe.ps1  ->  health.txt  ->  GitHub Actions: filter.sh  ->  hosts-ai.txt
                                                                              |
                                                             repository_dispatch
                                                                              v
                                                    nextdns-sync  ->  rewrites в NextDNS
```

1. Проверка на ПК раз в час смотрит, какие адреса живы с твоего провайдера, и при
   изменении коммитит `health.txt`.
2. Коммит запускает сборку, `filter.sh` пересобирает `hosts-ai.txt`.
3. Проверка дожидается новой сборки и отправляет `repository_dispatch` в
   [nextdns-sync](https://github.com/ISa1m0n/nextdns-sync), тот накатывает rewrites в NextDNS.

Раннер GitHub стоит в США и блокировок РКН не видит, поэтому живость адресов проверяется
не здесь, а с домашнего ПК.

## Как применить

### NextDNS

Основной путь. Через [nextdns-sync](https://github.com/ISa1m0n/nextdns-sync): он берёт
`hosts-ai.txt` как источник rewrites и обновляет их по расписанию. Rewrites в NextDNS
действуют на домен **и его поддомены**, поэтому отдельные `www.*` там не нужны.

### Windows

Дописать записи из `hosts-ai.txt` в `C:\Windows\System32\drivers\etc\hosts`
(нужны права администратора). Удобнее держать их отдельным блоком с маркерами
`BEGIN` / `END`, чтобы обновлять целиком.

### Keenetic

В Web CLI (`<роутер>/a`) - по строке на домен:

```
ip host chatgpt.com 31.25.239.132
```

Адрес берите из `health.txt` (строка `MAIN`), он меняется. Посмотреть, что уже прописано:
`show running-config`, искать строки `ip host`.

> [!WARNING]
> У Keenetic максимум **256** статических записей `ip host`, из них 2 служебных.
> 295 доменов туда не влезают: часть придётся выбрать или вынести на NextDNS.
> Записи `ip host` перебивают NextDNS, поэтому старый адрес там будет ломать домены
> на всех устройствах.

## Сборка

`filter.sh` запускается в GitHub Actions и проходит шесть шагов:

1. Скачивает свежие `hosts/eu/hosts` и `hosts/us/hosts` из апстрима.
2. Оставляет только разделы из `sections.txt`. Если раздел переименовали - сборка
   падает с ошибкой, а не выкидывает сервис молча.
3. Добавляет домены из `extra-domains.txt` - из любых разделов, независимо от выбора.
4. Подменяет домены из `us-domains.txt` строками US-hosts с указанным IP.
5. Выкидывает домены из `skip-domains.txt` - те, что всё равно блокирует список
   рекламы NextDNS (rewrite до них не доходит).
6. Выбирает живые адреса: `MAIN`, `ALT` и `GEMINI` берутся из `health.txt`, а если его
   нет - из `defaults.txt`. Все остальные "ядровые" EU-адреса считаются плохими, поэтому
   каждый домен идёт на `MAIN`. Затем применяются `bad-ips.txt`, закрепления из
   `pin-ips.txt` (`@MAIN`, `@ALT`) и последним слоем `custom-hosts.txt` (`@GEMINI`).

### Два режима сборки

`filter.sh` смотрит, откуда взялся `MAIN`:

- **filter** - `MAIN` (и `ALT`, если он задан отдельно) есть среди основных адресов
  EU-hosts. Берутся строки апстрима, плохие IP выкидываются. Обычный режим.
- **rewrite** - адрес пришёл из аварийного пула (сторонний DoH), в hosts GeoHide его нет.
  Тогда из апстрима берётся только список доменов, а IP ставится свой: `MAIN` для всех,
  закрепления из `pin-ips.txt` и `us-domains.txt` поверх. В Actions появится
  предупреждение `::warning::`, но сборка не падает.

Второй режим появился после 22.11.2026. Тогда все EU-адреса GeoHide перестали отвечать,
проверка записала в `health.txt` адрес из стороннего DoH, а `filter.sh` требовал `MAIN`
из ядра EU-hosts. Сборка падала, `hosts-ai.txt` оставался со старым мёртвым адресом,
и всё тихо ломалось. Падать в такой ситуации хуже, чем собрать список на единственном
живом адресе.

### Защиты

- **Разделы.** Незнакомое имя в `sections.txt` валит сборку: лучше красный крестик,
  чем молча выкинутый сервис.
- **US-пары.** В `us-domains.txt` каждая пара домен и IP должна найтись в US-hosts.
- **Массовая потеря.** Если записей собралось меньше 200 или их стало меньше 80% от
  прошлого файла, сборка падает и `hosts-ai.txt` не меняется.
- **Гонка с проверкой.** Push идёт с повторами и `pull --rebase`: бот и проверка коммитят
  в один репозиторий.

## Проверка адресов с ПК

`tools/geohide-probe.ps1`, задача в Планировщике раз в час. Полный перебор адресов -
раз в 3 часа: TLS до `claude.ai`, `chatgpt.com` и `platform.claude.com` по каждому
EU-адресу, выбор `MAIN` (самый быстрый живой) и `ALT` (второй), плюс поиск адреса
для Gemini без `google.com/sorry`.

В остальные запуски перебора нет: проверяются только текущие `MAIN` и `ALT` одним
запросом, работа занимает пару секунд. Если один из них умер, полный перебор идёт сразу,
не дожидаясь трёх часов.

### Закреплённые домены и их самолечение

Домены, которым нужен конкретный адрес, лежат в `custom-hosts.txt`: `opencode.ai`,
`www.opencode.ai` и `models.dev` на Cloudflare (`104.18.10.66`), `openrouter.ai` на живой
прокси. Причины разные: OpenCode прокси GeoHide не обслуживает, а OpenRouter наоборот
напрямую отдаёт 403 «Access denied by security policy» на своих же адресах Cloudflare,
то есть режет российский IP.

Каждый запуск проба проверяет все пины из `custom-hosts.txt` отдельным запросом. Код 403
живым ответом не считается: для закрепления это как раз признак, что адрес не годится.

Мёртвый пин скрипт лечит сам: берёт кандидатов из ответов DoH (прямые адреса домена),
затем из живых прокси, подставляет первый, который реально ответил, переписывает
`custom-hosts.txt` через API, ждёт пересборку `hosts-ai.txt` и вызывает nextdns-sync. Если
и это не помогло, приходит уведомление с просьбой проверить файл руками.

Проверено 27.11.2026 на заведомо мёртвом адресе `192.0.2.1` у `deepl.com`: проба
заменила его на `179.236.130.10` из ответа DoH, дождалась пересборки и вызвала nextdns-sync.

### Аварийный пул и покрытие

Если ни один EU-адрес GeoHide не отвечает, кандидаты берутся у сторонних DoH из
`tools/doh-servers.txt`. Такой адрес становится `MAIN` только в этом режиме, источник
пишется в `health.txt` строкой `# source:`.

Сторонний прокси часто знает не все домены: например, `dns.geodema.love` отдаёт ChatGPT
и Claude, но не отдаёт OpenRouter. Поставить его в `MAIN` - значит собрать список,
применить его в NextDNS и молча потерять часть сервисов. Поэтому покрытие считается
до выбора: скрипт проходит по `tools/coverage-domains.txt`, берёт адрес с большим числом
живых доменов, при равенстве - более быстрый. Результат пишется в `health.txt` строкой
`# coverage: 11/12`, а если покрытие ниже 75% - приходит уведомление со списком того,
что не работает.

Домены в `coverage-domains.txt` должны быть из `hosts-ai.txt`. Google-домены туда
не входят: они идут через `GEMINI` из `custom-hosts.txt`.

### Когда жив только один адрес

Тогда `ALT` совпадает с `MAIN`, и проверка пишет об этом в журнал. Разнос `www` и apex
пропадает, а это была работа вокруг last.fm: когда `www.last.fm` и `last.fm` смотрят
на один IP, Firefox склеивает соединения и сайт может ответить 403. Пока жив один
адрес, обойти это нечем: нужен другой адрес, а не настройка.

### Проверка сборки

Каждый запуск сверяет, что в `hosts-ai.txt` форка есть строки с текущим `MAIN`. Адрес
может быть живым, а сборка - красной, и тогда в NextDNS уедут старые адреса. Именно так
и случилось 22.11.2026: проверка писала «без изменений», а список стоял мёртвый. Теперь
в таком случае приходит уведомление в трей.

### Уведомления и журнал

Уведомление в трее приходит, когда живых адресов нет, Gemini деградировал, сборка
не обновилась или покрытие ниже 75%. Одно и то же событие показывается не чаще раза
в 6 часов. Журнал: `tools/geohide-probe.log`.

При включённом VPN или запущенном zapret проверка пропускается: результат был бы ложным.
Статус Gemini пишется в `health.txt` комментарием: `clean` (чат работает),
`ai-only` (чат отдаёт `/sorry`, живой только AI Studio), `dead` (не отвечает ничего).

### Установка

1. Склонировать репозиторий (например, `D:\OpenCode\ai-hosts`).
2. Положить рядом со скриптом токен: `tools\geohide-probe.token` - fine-grained,
   репозитории `ISa1m0n/ai-hosts` и `ISa1m0n/nextdns-sync`, право Contents: Read and write.
3. Задача в Планировщике: `wscript.exe "D:\OpenCode\ai-hosts\tools\run-probe-hidden.vbs"`,
   повтор каждый час, от имени текущего пользователя. Запускать `powershell.exe`
   напрямую нельзя: `-WindowStyle Hidden` прячет консоль уже после её создания, окно
   успевает мигнуть и снимает с фокуса игру в полноэкранном режиме. `wscript.exe` -
   GUI-приложение, консоль не создаётся вовсе; сам VBS стартует PowerShell скрытым
   и ждёт его завершения, чтобы Планировщик видел реальный статус задачи.
4. Проверить вручную: `powershell -File tools\geohide-probe.ps1 -DryRun` - покажет
   выбранные адреса и ничего не закоммитит.

Параметры: `-DryRun` (ничего не коммитить), `-Force` (не пропускать при VPN и zapret),
`-ForceCommit` (перезаписать `health.txt` без изменения адресов, чтобы прогнать цепочку),
`-NoNotify` (без уведомлений).

> [!IMPORTANT]
> `.ps1` должен лежать в UTF-8 **с BOM**. Веб-редактор GitHub срезает BOM, и тогда
> PowerShell 5.1 читает файл как cp1251: скрипт работает, но все русские сообщения
> в журнале и в трее превращаются в мусор. Правьте файл через git и проверяйте BOM:
> первые три байта должны быть `EF BB BF`. На `filter.sh` это не распространяется -
> bash BOM ломает.

Правки в клоне начинать с `git pull`: бот коммитит `hosts-ai.txt`, а проверка - `health.txt`.

## Структура

| Файл | Роль |
|---|---|
| `hosts-ai.txt` | **готовый список** - его и забирают |
| `sections.txt` | какие разделы апстрима оставить |
| `extra-domains.txt` | домены вне выбранных разделов |
| `us-domains.txt` | домены, которые берутся из US-hosts |
| `pin-ips.txt` | закрепить домен и его поддомены на одном IP |
| `custom-hosts.txt` | ручные записи поверх всей сборки; мёртвые пины проба лечит сама |
| `bad-ips.txt` | адреса, которые нельзя использовать |
| `skip-domains.txt` | домены, которые незачем включать (их блокирует список рекламы NextDNS) |
| `defaults.txt` | адреса по умолчанию (`MAIN`, `ALT`, `GEMINI`) |
| `health.txt` | **живые адреса**, пишет проверка с ПК, перекрывает `defaults.txt` |
| `tools/geohide-probe.ps1` | проверка адресов с ПК по расписанию, коммитит `health.txt` |
| `tools/doh-servers.txt` | сторонние DoH: адреса для Gemini и аварийный пул |
| `tools/coverage-domains.txt` | домены для оценки покрытия аварийного адреса |
| `tools/run-probe-hidden.vbs` | запускает проверку без окна консоли (действие задачи Планировщика) |
| `filter.sh` | сам сборщик |
| `.github/workflows/` | расписание, пересборка по push, keepalive |

## Если что-то не открывается

1. **Что отдаёт DNS.** `nslookup chatgpt.com` - должен вернуть адрес из `health.txt`.
   Если адрес другой или старый, дело в NextDNS, а не в прокси.
2. **Что в `health.txt`.** Строка `MAIN` - текущий адрес, `# checked` - когда проверяли,
   `# source:` - откуда он взят (`GeoHide EU` или `DoH`), `# coverage:` - сколько доменов
   адрес реально проксирует.
3. **Что в Actions.** Красная сборка на шаге Build filtered hosts - смотри сообщение:
   переименованный раздел, отсутствующая US-пара или сработавшая защита от потери.
4. **Что в журнале.** `Get-Content tools\geohide-probe.log -Tail 20` - видно, какие
   адреса проверялись и почему выбран текущий.
5. **Проверить руками.** `powershell -File tools\geohide-probe.ps1 -DryRun` покажет,
   что скрипт выберет сейчас, и ничего не изменит.

## Как менять

- **Добавить сервис** - дописать раздел в `sections.txt` (название должно точно
  совпадать с заголовком `# ...` в `hosts/eu/hosts` апстрима).
- **Один домен** - добавить в `extra-domains.txt`.
- **Свой IP** - `custom-hosts.txt`, формат `домен IP`. Мёртвый пин проба вылечит сама:
  подберёт прямой адрес из ответов DoH, а если тот не годится (у `openrouter.ai` прямой
  ответ 403 - Cloudflare режет российский IP) - живой прокси.
- **Убрать адрес** - `bad-ips.txt`. Только те, что не работают никогда (US-серверы,
  диапазоны, которые режет провайдер). Живой EU-адрес туда вносить нельзя: проверка
  может выбрать его в `health.txt`, а сборка выкинет все строки с ним.
- **Добавить сторонний DoH** - строка `https://хост/dns-query` в `tools/doh-servers.txt`.
- **Проверять больше сервисов** - домены в `tools/coverage-domains.txt`.

После правки пересборка стартует сама: workflow слушает `push` по этим файлам.

## Что изменено относительно апстрима

- Выбрано 30 разделов из ~50. Убраны `Canva`, `Chess`, `Oracle`, `Supercell` и др.:
  GeoHide их не проксирует, а обычный DNS для них лучше.
- `custom-hosts.txt` закрепляет Gemini и AI Studio на адресе `@GEMINI`: в hosts GeoHide
  живых адресов без `google.com/sorry` не осталось.
- `us-domains.txt` отключён: US-адреса GeoHide перестали отвечать.
- Добавлен `skip-domains.txt` - домены, которых незачем включать (их блокирует
  список рекламы NextDNS, rewrite до них не доходит).
- Добавлены `tools/doh-servers.txt` и `tools/coverage-domains.txt` - аварийный пул
  сторонних DoH и домены для оценки его покрытия.
- `custom-hosts.txt` умеет самовосстановление: мёртвый пин проверка заменяет сама
  (DoH, затем живой прокси) и вызывает nextdns-sync. `openrouter.ai` закреплён на прокси,
  потому что напрямую Cloudflare отдаёт 403 и никакой DNS-подменой это не лечится.
- `filter.sh` умеет режим `rewrite`: если `MAIN` пришёл из DoH и его нет в hosts
  GeoHide, список собирается на нём, а не остаётся старым.
- Удалены служебные копии `lists/` и `hosts/*` - сборка их не использует,
  всё качается из апстрима.
